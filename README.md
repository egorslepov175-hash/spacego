# SPACEGO

Сайт по опубликованному чату, предоставленному пользователем. Каталог аренды пространств в Новосибирске, адаптивный интерфейс, карта с ценами, избранное, бронирования, местная переписка, профиль и кабинет владельца.

## Запуск

Node.js 22+: `node preview.mjs`, затем `http://127.0.0.1:4173`.
Проверки расчётов и доступности: `node --test test/domain.test.mjs`.
Готовые статические файлы находятся в `dist/`, настройки публикации в `.openai/hosting.json`.

## GitHub Pages

Публикация настроена в `.github/workflows/pages.yml`. В настройках репозитория выберите **Settings → Pages → Source → GitHub Actions**. Отправка изменений в `main` или `master` запускает проверки бронирования и QR, затем публикует только папку `dist/`. Workflow также можно запустить вручную из **Actions**.

Ссылка на сайт появляется в успешно завершённой задаче публикации в окружении `github-pages`. Сайт поддерживает размещение в подпапке репозитория: ресурсы подключаются по относительным путям, навигация работает через `#`. Данные на новом домене сохраняются отдельно от локальной версии.

## Границы версии

Это работающий локальный прототип. Объявления и цены демонстрационные. Данные сохраняются в localStorage данного браузера и домена. Профиль не является серверной учётной записью; синхронизации между устройствами нет. Сообщения не отправляются другим людям. Платежи, возвраты, PIN и доступ к объектам только имитируются. Реальные платёжный провайдер, сервер, уведомления и замки не подключены.

Карта загружается через Leaflet/OpenStreetMap. Адрес можно открыть в Яндекс Картах. Фотографии и их лицензии перечислены на странице `credits.html`.

## QR-доступ после подтверждения

1. Заполните профиль, создайте бронь и подтвердите тестовую оплату.
2. В карточке бронирования нажмите «Получить код доступа», затем «Отправить профиль владельцу».
3. Перейдите в «Кабинет владельца · демо» или «Мои пространства». В разделе «Заявки на доступ» откройте «Проверить профиль» и подтвердите его.
4. Вернитесь в бронирование. Появится «QR-код для входа» с возможностью скачивания и проверки пропуска.

QR содержит случайный идентификатор пропуска выбранной брони, без контактов арендатора. До начала аренды пропуск можно скачать, но локальная проверка не разрешает вход. Окончание аренды, отмена, отзыв допуска и изменение профиля делают пропуск недействительным. Профиль подтверждается отдельно для каждой брони. Владелец может отклонить заявку или отозвать допуск. В прототипе роли переключаются на одном устройстве: это не защищённая серверная авторизация и не интеграция с замком.

Проверки: `node --test test/domain.test.mjs test/access.test.mjs`. QR дополнительно декодируется независимым jsQR в тестах. Генерация выполняется локально библиотекой qrcode-generator 1.4.4 (MIT), контакты не отправляются стороннему QR-сервису. В шапке используется оригинальный логотип пользователя, файл `dist/assets/spacego-logo.jpg`; поля изображения обрезаны только средствами CSS.
