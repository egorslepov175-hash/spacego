# SPACEGO Smart Lock — QR Edition: backend

Сервер для ESP32‑2432S028R и веб-страницы доступа. Используется Cloudflare Worker с D1 через Sites. Код API и миграции также сохраняются в GitHub-проекте SPACEGO. Публичная страница устройства сама по себе не разрешает вход.

## Адреса

- Backend: `https://spacego-lock-api.slepovnew2.chatgpt.site`.
- Кабинет владельца: `/owner`.
- Страница арендатора: `/access/d_<32 hex>`.
- Проверка доступности: `/api/health`.
- QR на ESP32 ведёт на `https://egorslepov175-hash.github.io/spacego/#device/d_<32 hex>`.

Эти адреса — конфигурация проекта; факт публикации проверяется отдельно при развёртывании.

## Кто разрешает открытие

Пользователь входит через ChatGPT на домене backend. Доверенные заголовки личности добавляет шлюз Sites; Worker авторизует каждую операцию. Владелец назначается серверной переменной `OWNER_EMAILS`. Не размещайте этот Worker за произвольным прокси, который пропускает пользовательские `oai-authenticated-user-*`: необходим проверенный шлюз идентификации.

Арендатор со страницы конкретного устройства отправляет заявку с датами. Владелец подтверждает бронь и отдельно отмечает фактическое получение оплаты. Подключения платёжного провайдера в этой версии нет. Самостоятельная отметка оплаты арендатором невозможна. Локальные демоброни старого каталога не импортируются как разрешения на открытие.

## Регистрация ESP32

1. Владелец входит в `/owner`, добавляет устройство и задаёт импульс 100–5000 мс.
2. Получает одноразовый код подключения, действующий 15 минут. Код предназначен для USB-настройки ESP32 и не включается в QR.
3. ESP32 генерирует собственный 256-битный ключ, сохраняет его до регистрации и передаёт код подключения, ключ и идентификатор регистрации только по проверенному HTTPS.
4. Сервер сохраняет ключ в D1 зашифрованным AES‑256‑GCM. Ключ шифрования хранится отдельным секретом окружения. Повтор регистрации с той же парой ключ/идентификатор безопасен; другое устройство не может повторно использовать код.
5. Сервер возвращает публичный ID и QR URL. Повторное подключение через кабинет отзывает прежний ключ и непереданные команды.

## Открытие и защита от повторов

`POST /api/devices/:id/open` требует аутентифицированного пользователя и `Idempotency-Key` UUID. Проверяются подтверждение, оплата, отсутствие отзыва, текущий срок и heartbeat устройства не старше 12 секунд. Между открытиями одного устройства — минимум 15 секунд. Команда живёт не более 12 секунд и не дольше оплаченной брони.

Устройство опрашивает `/api/device/poll` с новым challenge и boot ID. Каждый запрос подписан HMAC‑SHA‑256 и содержит timestamp и случайный nonce; использованный nonce повторно не принимается. Сроки и отзыв брони перепроверяются при передаче команды. Атомарный SQL-захват предотвращает повторную выдачу при одновременных опросах. Переданная команда никогда не выдаётся повторно, даже если подтверждение потерялось.

Подпись команды привязывает её к устройству, последовательности, boot ID, challenge, сроку и длительности импульса. ESP32 сохраняет потреблённую последовательность в NVS до включения выхода. Потеря питания может привести к пропуску открытия, но не к повторному исполнению. `/api/device/ack` подтверждает завершение импульса. Без ACK интерфейс показывает неопределённый исход, а не обещает, что ворота открыты. Датчика положения ворот в данной конфигурации нет.

Отзыв блокирует ещё не переданные команды. Уже полученный устройством импульс невозможно отменить задним числом; максимальный срок команды и таймер ограничивают это окно. Потеря Wi‑Fi на ESP32 отключает выход, потеря сервера запрещает новые открытия.

## Переменные окружения

- `OWNER_EMAILS`: адреса подтверждённых аккаунтов владельцев через запятую, только на сервере.
- `DEVICE_KEY_ENCRYPTION_SECRET`: 32 случайных байта в hex, серверный секрет; не менять без миграции существующих ключей устройств.
- `PUBLIC_APP_URL`: публичный адрес каталога с завершающим `/`.
- `SITE_ORIGIN`: origin backend.

Секреты задаются через окружение хостинга, не попадают в GitHub или `.openai/hosting.json`. В репозитории только `.env.example`. Миграции `drizzle/` применяются хостингом до запуска Worker. Не меняйте уже применённую миграцию после первого развёртывания.

## Проверка и локальный просмотр

Нужен Node.js 22.13+ с `node:sqlite`:

```sh
node --test test/api.test.mjs
node scripts/build.mjs
node scripts/preview.mjs
```

Локальный просмотр: `http://127.0.0.1:4180`, тестовые роли — `/signin-with-chatgpt`. Preview слушает только loopback. Тестовые заголовки и роли находятся в `scripts/preview.mjs`, не входят в Worker и не подходят для публичного размещения. Продуктовая сборка — только `dist/server/index.js`.

Тесты проверяют отказ без оплаты/подтверждения, подмену подписи, replay nonce, идемпотентность, срок брони, отзыв, отсутствие связи, конкурентную выдачу команд и пересечение бронирований. Физическое срабатывание реле проверяется отдельно на макете.

## Протокол

Каноническая строка запроса, без завершающего перевода строки:

```text
SG-REQ-1\nPOST\n<path>\n<unix seconds>\n<64 hex nonce>\n<sha256 exact UTF-8 JSON body>
```

Заголовки: `X-Spacego-Device`, `X-Spacego-Time`, `X-Spacego-Nonce`, `X-Spacego-Signature`. Допустимое отклонение времени — 30 секунд; устройство должно синхронизировать NTP до работы TLS/API.

Каноническая строка команды, также без завершающего перевода строки:

```text
SG-CMD-1\n<device_id>\n<command_id>\n<seq>\n<issued_at>\n<expires_at>\n<pulse_ms>\n<boot_id>\n<challenge>
```

В обеих строках `\n` означает байт LF. Подпись — HMAC‑SHA‑256 ключом устройства, 64 строчных hex-символа. Все времена — целые Unix-секунды. JSON содержит `v: 1`. Ключ и подписанные команды не являются содержимым QR.
