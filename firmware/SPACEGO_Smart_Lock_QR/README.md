# SPACEGO Smart Lock — QR Edition

Полная прошивка для **ESP32‑2432S028R, TFT 2.8″, 240×320**. Этот вариант подготовлен под уточнённую пользователем плату со встроенным дисплеем. Он не предназначен для первоначально упомянутого отдельного E‑Ink 2.13″. Сенсор не инициализируется. Клавиатуры, ввода PIN и кнопки открытия на экране устройства нет.

## Что показывает экран

Оригинальный логотип SPACEGO, чёрно-белый QR на белом фоне с тихой зоной, «Отсканируйте для получения доступа» и статус связи. По подлинной разрешённой команде: «Доступ разрешён», «Ворота открываются», затем тот же публичный QR. Положение ворот не измеряется: подтверждается импульс реле.

## Подключение именно этой платы

Встроенный дисплей уже подключён производителем:

| Сигнал | GPIO |
|---|---:|
| TFT MOSI | 13 |
| TFT MISO | 12 |
| TFT SCK | 14 |
| TFT CS | 15 |
| TFT DC | 2 |
| TFT подсветка | 21 |
| Сенсор CS (удерживается HIGH) | 33 |
| Сенсор MOSI (не используется прошивкой) | 32 |
| Реле | **22**, выведен на P3/CN1 |

**GPIO 32 из первоначальной схемы не используется для реле:** на ESP32‑2432S028R он связан с XPT2046. Не переносите на эту плату схему проводов внешнего E‑Ink. GPIO 35 — только вход, для реле не подходит.

Основа распиновки: [проект ESP32-Cheap-Yellow-Display, PINS.md](https://github.com/witnessmenow/ESP32-Cheap-Yellow-Display/blob/main/PINS.md). У некоторых ревизий с USB-C установлен ST7789 вместо ILI9341; для них предусмотрена отдельная сборка `cyd_st7789`.

## Релейный модуль 5 V

По умолчанию прошивка рассчитана на active-LOW вход модуля **через NPN/MOSFET-согласование**, поэтому на GPIO 22 активен HIGH:

```text
GPIO22 ── 1 кОм ── база NPN (например, 2N2222)
                     │
                   10 кОм
                     │
GND ESP32 ───────────┴── эмиттер NPN ── GND реле
IN реле ──────────────── коллектор NPN
VCC реле ──────────────── отдельные стабильные 5 V
```

Резистор 10 кОм удерживает NPN выключенным при загрузке/сбросе. Не подавайте 5 V на GPIO ESP32. Если вход модуля сам подтянут к 5 V, прямое подключение запрещено: нужен согласующий каскад. Питание катушки не берите с 3.3 V платы. Контакты COM/NO используются как управляющий сигнал макета, а не для непосредственного питания двигателя.

Если используется модуль с документированной совместимостью входа с 3.3 V и прямым active-LOW управлением, задайте `SPACEGO_RELAY_ACTIVE_HIGH false` в `secrets.h` и обеспечьте внешний pull-up к **3.3 V**, чтобы вход оставался неактивным при reset. Это другая схема; не смешивайте её с описанным выше NPN-каскадом.

## Быстрый запуск готового .bin

1. Скачайте из GitHub Releases **`SPACEGO_QR_CYD_ILI9341_full.bin`** для обычного ESP32‑2432S028R. Для ревизии ST7789 используйте соответствующий `_ST7789_full.bin`.
2. Отключите нагрузку реле на время первой прошивки и проверки состояния выхода.
3. Установите Python и инструменты:

   ```sh
   python -m pip install esptool==4.8.1 pyserial==3.5
   ```

4. Подключите плату USB-кабелем с передачей данных. Найдите её COM-порт и прошейте полный образ с адреса **0x0**:

   ```sh
   python -m esptool --chip esp32 --port COM5 --baud 460800 write_flash 0x0 SPACEGO_QR_CYD_ILI9341_full.bin
   ```

   При необходимости удерживайте BOOT во время соединения, отпустите после начала записи. Замените COM5 своим портом. Альтернатива — `tools/flash.ps1`.

5. После прошивки войдите в [кабинет владельца](https://spacego-lock-api.slepovnew2.chatgpt.site/owner), добавьте «Ворота макета» и получите код подключения. Код живёт **15 минут**, поэтому создавайте его после завершения длительной компиляции/прошивки.
6. Закройте Serial Monitor и выполните из папки исходников:

   ```sh
   python tools/configure_device.py
   ```

   Укажите COM-порт, Wi‑Fi **2.4 GHz**, пароль и свежий код владельца. Пароль и код не выводятся и не передаются аргументами командной строки. Настройки сохраняются в NVS. Плата перезапустится, синхронизирует часы, зарегистрируется и покажет QR.
7. Сканируйте QR телефоном. Войдите в аккаунт арендатора, запросите бронь на нужное время. Владелец отдельно подтверждает бронь и получение оплаты. Только во время такой брони доступна кнопка «Открыть ворота».

Для смены только Wi‑Fi запустите USB-настройку и оставьте код подключения пустым. Для повторного подключения устройства получите новый код в кабинете и введите его через USB. Прошивка не сохраняет секреты в QR.

## Сборка из исходников

```sh
python -m pip install platformio==6.2.0
pio run -e cyd_ili9341
pio run -e cyd_ili9341 -t upload
pio device monitor -b 115200
```

Вариант для ST7789: замените среду на `cyd_st7789`. `platformio.ini` фиксирует ESP32 Arduino 2.0.17 через `espressif32@6.9.0` и версии библиотек. Без `secrets.h` сборка не содержит Wi‑Fi или кода подключения и настраивается через USB. При желании скопируйте `include/config.example.h` в `include/secrets.h` и заполните данные перед сборкой; этот файл исключён из Git и архива исходников. Не публикуйте персонально настроенный `.bin`, если в него включили собственные секреты.

`_app.bin` предназначен для адреса **0x10000** после корректной записи загрузчика и таблицы разделов. Для первого запуска используйте `_full.bin` с 0x0. Полный образ содержит загрузчик, таблицу `huge_app.csv`, boot_app0 и приложение. Flash — 4 MB, PSRAM не требуется, OTA не реализована.

## Backend и протокол

Backend: `https://spacego-lock-api.slepovnew2.chatgpt.site`.

- `POST /api/device/register`: одноразовое подключение по HTTPS.
- `POST /api/device/poll`: опрос раз в 2 секунды, HMAC-подпись запроса, свежие nonce/challenge и boot ID.
- `POST /api/device/ack`: подписанное подтверждение завершения импульса.
- `POST /api/devices/:id/open`: запрос пользователя; доступен только через серверную авторизацию и действующую бронь.

Канонические строки и модель данных описаны в README серверной части `lock-backend/`. ESP32 не использует данные `localStorage` каталога и не получает ключи из браузера арендатора.

## Что проверяет прошивка

- Подлинность TLS-сертификата и имени HTTPS-сервера. `setInsecure()` не используется. Включены публичные GTS Root R4 и ISRG Root X1; при смене цепочки доверия обновите `trust_roots.h` и прошивку, а не отключайте проверку.
- Правильные HMAC‑SHA‑256, устройство, boot ID и challenge.
- Целые поля протокола, TTL до 15 секунд, срок команды, безопасную длительность импульса.
- Уникальную возрастающую последовательность с сохранением в NVS **до** включения GPIO.
- Локальный интервал между импульсами минимум 15 секунд.

Реле выключено в начале `setup`, при ошибках и потере Wi‑Fi. Отдельный `esp_timer` выключает выход, даже если обновление TFT задержалось. Максимальный импульс 5 секунд; значение владельца 100–5000 мс проверяется обеими сторонами. Обрыв питания до исполнения может потерять команду; повторное открытие не выполняется автоматически.

Ключ устройства хранится в NVS. Обычная сборка для макета не защищает его от физического считывания flash: для реальных объектов необходимы Secure Boot, Flash Encryption, защищённое питание и проверенная электрическая часть. В этой конфигурации нет датчика положения ворот, защиты от защемления или контроля исправности механики.

## Ошибки

| Статус | Что проверить |
|---|---|
| «Настройте через USB» | Запустить `configure_device.py` |
| «Нет подключения Wi‑Fi» | SSID/пароль, сеть 2.4 GHz, питание |
| «Синхронизация времени» | Доступ к NTP и интернету |
| «Код истёк: обновите» | Новый 15-минутный код в кабинете |
| «Устройство отключено» | Статус устройства/ключа у владельца |
| «Нет связи с сервером» | HTTPS, DNS, корневые сертификаты, API |
| «Ошибка NVS» | Не подключать нагрузку; проверить flash/питание |
| Белый/перевёрнутый экран | Уточнить ревизию, попробовать сборку ST7789 |

## Проверка на макете

Сначала проверьте выход без нагрузки при включении, reset, отсутствии Wi‑Fi и недоступном API: импульса быть не должно. Затем проверьте разрешённое открытие, отказ до/после срока, отзыв, повтор HTTP-запроса, перезагрузку после команды и отключение сети во время импульса. Сверьте длительность импульса измерителем/логическим анализатором. Программная сборка и тесты не заменяют эту аппаратную проверку.
